# 双手机与视觉标记验证全过程

本流程使用两台固定手机和刚性视觉标记，为双接收器电磁手臂重定向提供独立的视觉参考。
第一次执行时机器人不运动，只比较视觉估计与 EM 估计。相机标定、人体标记对齐和正式评价
是三组不同的数据，不能混为同一次试验。

手机系统经过标定后仍属于实验参考系统，不是无误差的计量设备。论文中应报告它的重投影
误差、双相机一致性和可见率，并使用“视觉参考”而不是“绝对无误差真值”。

## 1. 所需物品

| 物品 | 数量 | 要求 |
|---|---:|---|
| 手机 | 2 | 后置主摄可录制 1080p/60 fps；型号可以不同 |
| 稳定支架 | 2 | 手机固定后不能移动 |
| ChArUco 标定板 | 1 | A3、8×6 方格、方格 40 mm、内部标记 30 mm |
| 大臂 ArUco 板 | 1 | ID 10，黑色方框边长 60 mm，底板约 80×80 mm |
| 前臂 ArUco 板 | 1 | ID 20，黑色方框边长 60 mm，底板约 80×80 mm |
| LED 或可快速变黑/变白的屏幕 | 1 | 必须能同时出现在两台手机画面中 |
| 泡沫板、硬纸板或塑料薄板 | 若干 | 保证标定板和人体标记平整 |
| 胶带或非金属绑带 | 若干 | 固定 EM 设备和小标记板 |

统一使用 OpenCV `DICT_4X4_50`。打印时选择 `100%` 或“实际尺寸”，关闭“适应页面”。打印
后测量实际黑色方框和棋盘格尺寸，并记录实际值。不要使用反光覆膜。

## 3. 两台手机设置和位置

两台手机都设置为：

- 横屏；
- 后置 `1×` 主摄；
- `1920×1080, 60 fps`；
- 关闭数字变焦、HDR、电子防抖和自动镜头切换；
- 尽量锁定焦距、曝光和白平衡；
- 不使用超广角镜头；
- 手机保持充足电量和存储空间。

手机 A 放在测试人员正前方，手机 B 放在测试人员左前侧或左侧。两个光轴夹角建议约
`60–90°`，镜头高度约为肩与肘之间。两台手机距离左肩约 `1.5–2.5 m`，并且都要完整看到：

- 左肩；
- 左肘；
- 左腕；
- 左臂前举、侧举和斜向举的整个空间。

不要把手机和金属三脚架放到 EM 发射器附近。最终位置确定后，在正式使用 EM 前进行一次
静止噪声检查。实验地面用胶带标出两个三脚架脚的位置。如果任一手机后来发生平移、旋转或
支架下沉，必须重新做第 5 节的双相机外参；如果分辨率、镜头、对焦/变焦或防抖模式改变，
则第 4、5 节都要重做。

## 4. 每台手机的内部参数标定

内部参数包括焦距、主点和镜头畸变。手机固定在正式实验位置，使用正式录像分辨率和镜头。

1. 开启两台手机录像；
2. 拿着安装在硬板上的大 ChArUco 板进入画面；
3. 依次把板放到画面中央、四角、上方、下方、近处和远处；
4. 改变板的俯仰、偏航和滚转角度；
5. 每个位姿停稳 `1–2 s`；
6. 每台手机至少取得 `25–40` 张清晰、完整且差异明显的图像；
7. 手只能握背面手柄或图案外的空白边缘；
8. 结束录像并保存原始文件。

不要只让标定板始终正对相机，也不要只在画面中央移动。过度倾斜导致图案无法识别的帧直接
丢弃。

后续 OpenCV 标定应输出每台手机的相机矩阵、畸变参数和每张图的重投影误差。工程目标为
平均重投影误差小于约 `1 pixel`，优先争取小于 `0.5 pixel`。若误差大或图像只覆盖画面
中央，重新采集。

## 5. 两台手机之间的外部参数标定

外部参数描述手机 A 坐标系到手机 B 坐标系的固定变换。

1. 两台手机保持固定并同时开始录像；
2. 把大 ChArUco 板放到未来左臂运动的共同可见空间；
3. 大部分时候让板面朝向两台手机之间，使两边都能完整识别；
4. 在肩部、肘部、胸前、身体左侧、较高、较低、较近和较远处采集；
5. 每个位姿静止 `1–2 s`；
6. 采集 `15–20` 对两台手机均清晰可见的匹配图像；
7. 停止录像，拿走大标定板；
8. 从此刻起不得移动手机。

由于每个位姿静止保持，两台手机暂时不需要硬件同步。后处理时为每个位姿从 A、B 视频各选
一张处于同一静止状态的图像。

外参完成后，用一个固定小标记在共同视野内做自检：分别由两台手机估计其姿态并转换到共同
坐标系。两边估计的标记方向应接近，方向差优先控制在 `2–3°` 以内。这个差值应作为视觉
参考系统自身的不确定度报告，而不能隐藏。

## 6. 安装 EM 设备和人体小标记

相机标定完成后，依次安装：

1. 胸部 EM 发射器；
2. 左大臂 EM 接收器；
3. 左前臂 EM 接收器；
4. 大臂 ArUco ID 10；
5. 前臂 ArUco ID 20。

小板安装要求：

- 使用轻质、平整的非金属底板；
- 大臂板固定在大臂外侧，前臂板固定在前臂外侧；
- 不跨越肩、肘或腕关节；
- 尽量靠近对应 EM 接收器，但不能遮住或挤压接收器；
- 板的长边尽量沿肢段长轴；
- 板和接收器使用独立胶带固定，避免拉扯一个设备时带动另一个；
- 安装后用手轻触检查，板不能相对皮肤明显摆动。

如果单张平面标记在常用动作中频繁侧对两台相机，可以使用轻量 L 形双面标记载体。载体上
不同标记之间的相对姿态必须固定并在软件中记录。

## 7. 可见性和环境检查

在运行机器人前完成以下检查：

1. 两台手机开始一段短录像；
2. 做直臂下垂、前举、侧举和弯肘；
3. 检查 ID 10 和 ID 20 是否清楚、是否反光；
4. 检查标记是否被衣服、躯干或另一段手臂遮挡；
5. 确认主要测试姿势中，每个标记至少被一台手机稳定看到；
6. 更严格的三维评价帧应优先要求两个手机同时检测成功；
7. 手机和三脚架就位后运行 EM 静止检查，确认没有明显增加噪声。

手机原生录像界面不会显示 ArUco ID。把短视频原文件复制到电脑，用项目中的检查工具分别
处理手机 A 和 B：

```bash
conda activate unitree-rl
cd ~/humanoid_mpc_ws/src/wb_humanoid_mpc

python humanoid_nmpc/remote_control/scripts/aruco_video_check.py \
  ~/Videos/phone_A_visibility.MOV

python humanoid_nmpc/remote_control/scripts/aruco_video_check.py \
  ~/Videos/phone_B_visibility.MOV
```

程序默认查找 `DICT_4X4_50` 中的 ID 10 和 20，并生成：

```text
phone_A_visibility_aruco_check.mp4
phone_A_visibility_aruco_check.json
```

带框视频中绿色 `VISIBLE` 表示当前帧识别到对应 ID，红色 `NOT SEEN` 表示该帧没有识别。
JSON 和终端会报告每个 ID 的识别率、标记在画面中的像素边长和最长连续丢失时间。第一次
检查至少要求两段视频合起来确实识别到 ID 10、20；正式三维测试还应尽量提高“两台手机
同时看到两个 ID”的帧比例。若完全识别不到，优先检查字典、打印 ID、反光、运动模糊、
标记尺寸和摄像距离。

标记不可见时，先调整相机角度或标记位置。调整相机后必须重新做相机外参；调整人体标记或
EM 接收器后必须重新做第 8 节的当次安装标定。

## 8. 当次安装的 EM 标定和视觉标记对齐

每次设备从身体取下后都执行本节，只使用本次成功的标定。机器人和 MuJoCo 均不运行。

### 8.1 启动 EM 数据

Docker 终端 1：

```bash
source /wb_humanoid_mpc_ws/install/setup.bash
ros2 run remote_control dual_em_tracker_node
```

确认出现第一对同步数据，且没有持续的四元数模长、失联或过期警告。

### 8.2 开始对齐录像

1. 开启手机 A、B 的录像；
2. 在两台手机都可见的位置让 LED 快速亮灭两次；
3. 保持 `DOWN` 约 3 秒；
4. 做一次约 `20°` 的明显肘部屈伸并返回，作为视频与 EM 的同步动作；
5. 再保持 `DOWN` 约 3 秒。

LED 只用于对齐手机 A 与 B；肘部同步动作同时出现在视觉轨迹和 EM 轨迹中，用于对齐视频与
ROS 日志。同步动作不计入正式评价。

### 8.3 运行双接收器标定

Docker 终端 2：

```bash
source /wb_humanoid_mpc_ws/install/setup.bash
ros2 run remote_control dual_calibration_node
```

严格按照终端提示完成静止检查、接收器分配检查和所有参考姿势。两台手机全程继续录像。
其中 `DOWN、FORWARD、SIDEWAYS` 同时用于拟合：

```text
双手机共同坐标系 -> 人体躯干/EM发射器坐标系
大臂标记坐标系 -> 大臂肢段方向
前臂标记坐标系 -> 前臂肢段方向
```

第一项把视觉方向转换到与 EM 输出相同的人体坐标轴；后两项修正每个标记安装角度造成的
固定旋转偏置。三个参考姿势应联合求解这些固定旋转。不要直接假设相机轴、人体轴和小板
边缘天然平行，也不能把两个坐标系中的向量直接相减。

标定成功后保存 YAML 和 reference NPZ。停止两台手机录像，文件命名为：

```text
phone_A_alignment.mp4
phone_B_alignment.mp4
```

这一段数据只用于 EM 标定和视觉标记对齐，不作为最终精度测试数据。

## 9. 独立评价数据采集

设备、小板和手机均保持不动。机器人与 MuJoCo 仍然不运行。

### 9.1 启动 dry-run 重定向

Docker 终端 2：

```bash
source /wb_humanoid_mpc_ws/install/setup.bash
ros2 run remote_control dual_retargeting_node
```

不添加 `publish_joint_targets:=true`。确认终端显示 joint-target publishing disabled，并确认全
频率 diagnostic recording 已启用。

### 9.2 新录像与同步

1. 两台手机开始新的录像；
2. LED 快速亮灭两次；
3. `DOWN` 保持 3 秒；
4. 做一次约 20° 的肘部同步动作并返回；
5. `DOWN` 再保持 3 秒；
6. 开始下面的正式动作。

如果有协助者，由协助者读出动作编号和操作 LED。没有协助者时，可提前播放带语音提示的
定时音频；不要为了操作手机在试验中途离开姿势。

### 9.3 正式动作顺序

所有动作缓慢进行，每段移动用 `3–5 s`，终点保持 `5 s`。

| 编号 | 动作 | 重复 | 主要评价量 |
|---|---|---:|---|
| 0 | `DOWN` 静止 | 1 | 零位和静止噪声 |
| 1 | 直臂下垂 | 3 | 肘角和方向重复性 |
| 2 | 直臂前举到约 30°、60°、90° | 各3 | 矢状面方向误差 |
| 3 | 直臂侧举到约 30°、60°、90° | 各3 | 额状面方向误差 |
| 4 | 前左斜向举到肩高 | 3 | 三维组合方向误差 |
| 5 | 大臂下垂，肘部缓慢屈伸 | 3往返 | 肘角误差和串扰 |
| 6 | 弯肘前举到 `FORWARD` 再返回 | 3往返 | 弯肘状态下的方向误差 |
| 7 | 下垂直接侧举到标准终点 | 2 | 路径 1 终点 |
| 8 | 下垂→前举→水平圆弧到侧举 | 2 | 路径 2 终点 |
| 9 | 保持手臂相对躯干不变，躯干左右转约15° | 2 | 躯干相对不变性 |

“约 30°、60°、90°”只是帮助覆盖工作范围，不要求人体凭感觉精确达到这些数值，实际角度
由视觉系统测量。肘完全伸直时不把肩部轴向旋转和前臂旋转作为主要精度指标。

### 9.4 结束同步和保存

1. 回到 `DOWN` 并保持 3 秒；
2. 再做一次约 20° 的肘部同步动作并返回；
3. LED 快速亮灭三次；
4. 停止两台手机录像；
5. 在 retargeting 终端按 `Ctrl+C`；
6. 确认终端打印 `Saved ... dual_retargeting_....npz`；
7. 记录 NPZ 完整路径和两个视频文件名。

起点和终点同步事件可以检查两台手机是否在长录像中发生时间漂移。

## 10. 视频和 EM 数据后处理

后处理按以下顺序进行：

1. 从原始视频读取每帧真实时间戳，不直接假定所有帧严格等间隔；
2. 检测 ChArUco/ArUco 角点，并记录检测置信度和重投影误差；
3. 使用手机内参估计 ID 10、ID 20 在各自相机中的姿态；
4. 使用双相机外参把所有结果变换到共同坐标系；
5. 两台手机同时可见时融合两次估计，并保存两者的差异；
6. 使用第 8 节参考姿势联合求视觉共同坐标系到人体/EM坐标系的旋转，以及两个标记到各自
   肢段方向的固定旋转；
7. 把视觉结果转换到人体/EM坐标系，再计算视觉大臂单位方向、前臂单位方向和肘角；
8. 使用 LED 帧对齐两段视频；
9. 使用肘部同步动作把视觉时间线与 retargeting NPZ 对齐；
10. 将视觉数据插值到 EM 时间戳；
11. 排除同步动作、移动过渡段和标记不可见帧；
12. 对每个保持段和动态段计算误差。

视觉肘角由两个肢段方向计算。方向误差为：

```text
e_upper = acos(clip(u_upper_EM · u_upper_visual, -1, 1))
e_forearm = acos(clip(u_forearm_EM · u_forearm_visual, -1, 1))
e_elbow = abs(theta_elbow_EM - theta_elbow_visual)
```

每项报告 `RMSE、median、P95、max`，并分别报告不同动作和不同重新佩戴次数。不要把所有
视频帧当作相互独立的实验样本；一次保持、一次动作往返和一次重新佩戴才是统计重复。

## 11. 数据质量和无效试验判定

以下情况整次重做：

- 任一手机或支架在相机外参标定后移动；
- 录像期间镜头自动切换；
- 大臂/前臂小板或 EM 接收器发生明显位移；
- 两段手机视频无法通过开始与结束事件对齐；
- retargeting NPZ 没有保存；
- EM 出现持续四元数异常或长时间中断；
- 动作顺序无法辨认。

以下情况可以只排除局部帧，并在论文中报告排除比例：

- 某个标记短暂遮挡；
- 单帧严重运动模糊；
- 单帧重投影误差超过预设阈值；
- LED 瞬间过曝，但动作轨迹仍可同步。

建议记录：两标记的双相机同时可见率、单相机可见率、剔除帧比例、最长连续丢失时间和两台
相机之间的方向估计差。

## 12. MuJoCo 阶段

只有第 9–11 节流程已经产生可信数据后，才开启 MuJoCo。保持相机和设备安装不变：

```bash
ros2 launch g1_centroidal_mpc mujoco_sim.launch.py
```

然后运行：

```bash
ros2 run remote_control dual_retargeting_node --ros-args \
  -p publish_joint_targets:=true \
  -p simulation_only:=true
```

选择前举、侧举、斜向举、路径一致性和胸前碰撞保护作为演示动作。保存 retargeting NPZ、MPC
日志和固定视角屏幕录像。若要公平比较不同算法版本，应回放同一条已经记录的目标轨迹，而不
是让人重新做一遍不同动作。

## 13. 真机阶段

真机不用于建立人体视觉参考，视觉参考应先独立验证。真机阶段继续使用手机记录人体，同时
使用 G1 编码器记录机器人实际角度：

```text
视觉参考 vs EM方向        -> 人体估计误差
EM目标 vs 安全层输出       -> 安全修正量
安全命令 vs G1编码器       -> 真机关节跟踪误差
G1 IMU和下肢编码器         -> 站立稳定性
```

严格遵循 `first_real_robot_run_zh.md`：先只读、固定 5°动作，再进行 5–10°慢速屈伸肘。
第一次真机在线跟随不做完整前举、侧举和靠近躯干动作。

## 14. 正式论文数据计划

推荐至少完成：

- 1 名主要参与者；
- 10 次独立拆卸、重新佩戴与重新标定；
- 每次都完成一组对齐标定和一组独立测试；
- 每个静态终点至少重新构建 3 次；
- 所有成功和失败试验均保留并说明原因。

如果有更多参与者，先确认学校的伦理和知情同意要求。只有一名参与者时，应把结论限定为
系统工程可行性和重复安装性能，不声称对所有人体具有普遍精度。

## 15. 第一次执行时的最小任务

第一次不要直接采集 10 次正式数据，只完成一轮预实验：

- [ ] 打印并测量大 ChArUco 板和两个小标记；
- [ ] 固定手机并录制相机标定视频；
- [ ] 计算并检查内参与外参；
- [ ] 安装 EM 和小标记；
- [ ] 录制对齐标定视频；
- [ ] 完成一次 dry-run 独立动作测试；
- [ ] 保存两个视频、标定 YAML、reference NPZ 和 retargeting NPZ；
- [ ] 成功画出视觉与 EM 的大臂方向、前臂方向和肘角三条对比曲线；
- [ ] 检查误差计算和时间同步后，再开始正式重复实验。

当前仓库已经能保存 EM 标定、重定向和真机日志，但双手机视频的自动标定、标记跟踪和时间
对齐脚本仍需单独实现。在这些脚本完成并用预实验验证前，不开始正式 10 次数据采集。
